# Assignment 4 Question 4

XYZCoin is an ERC20 token compiled with Solidity 0.5.1. Its name is XYZCoin, symbol is XYZ, decimals is 0, and fixed supply is 1000. The constructor allocates the entire supply to the deploying account.

## 4a Project initialization

Install the pinned dependencies with `npm ci`. The project follows the structure generated by `truffle init`:

- `contracts/`: Solidity source files.
- `migrations/`: numbered deployment scripts.
- `test/`: Mocha tests.
- `truffle-config.js`: network and compiler settings.

Compilation creates `build/contracts/` containing JSON artifacts with ABI, bytecode and deployment information. The Migrations tracking contract and numbered deployment scripts are included explicitly.

## 4b Configuration and compilation

The development endpoint is `http://127.0.0.1:9545`, matching Truffle Develop. The `development` network accepts the local network ID; the managed `develop` network uses ID 5777. The optimizer is enabled with 200 runs.

The compiler is loaded from `solc/soljson.js`, and `package.json` pins that package to exactly 0.5.1. This avoids a separate compiler download. Compilation reports `0.5.1+commit.c8a2cb62.Emscripten.clang`.

```powershell
npm ci
npm run compile
```

A compilation event handler removes the empty metadata field emitted for interfaces by Solidity 0.5.1. This lets Truffle 5.11.5 load the interface artifact in its console. It does not change source, ABI or bytecode.

## 4c Interface

`contracts/ERC20.sol` contains declarations only: the six standard token functions, the two events and the optional name, symbol and decimals getters. There are no function bodies or stored balances in the interface.

## 4d Balances and allowances

`contracts/XYZCoin.sol` imports and implements `ERC20.sol`.

`balances[owner]` stores the token balance of an address. `allowed[owner][spender]` stores how much a spender may transfer from that owner. An unused mapping entry is zero. Approving a spender grants permission without moving tokens.

## 4e Token functions

- `balanceOf` and `allowance` read the mappings.
- `transfer` moves tokens from the caller and emits `Transfer`.
- `approve` sets or replaces the caller's allowance and emits `Approval`.
- `transferFrom` checks and consumes the caller's allowance, transfers the owner's tokens and emits `Transfer`.
- Transfers of zero are successful and emit `Transfer`. Creation emits a `Transfer` from the zero address.

SafeMath checks arithmetic under Solidity 0.5.1. Transfers require sufficient funds; delegated transfers also require sufficient allowance. A revert rolls back the whole transaction, including an allowance reduction. The contract rejects zero recipients and zero spenders.

## 4f Migration

`migrations/1_initial_migration.js` deploys the tracking contract. `migrations/2_xyz_coin.js` deploys XYZCoin with `deployer.deploy(XYZCoin)`.

## 4g Deploy on the local development chain

From this directory, start the console:

```powershell
npm run develop
```

At the `truffle(development)>` prompt, enter these commands one at a time and wait for each to finish:

```text
migrate
exec scripts/verify-deployment.js
test
.exit
```

`truffle develop` starts the local chain and opens its console. `migrate` compiles as needed and executes the numbered deployment transactions. The constructor assigns all tokens to the creator. Truffle saves the contract addresses and tracks completed migrations. Use `migrate --reset` if you deliberately want to redeploy on the same running chain.

The verification command reads the deployed contract, checks its parameters and creator balance, and saves the deployment receipt details to `results/deployment.json`. Addresses and transaction hashes change on a new chain.

## 4h Basic Mocha tests

`test/xyz_coin.test.js` checks metadata, creator ownership of the total supply, direct transfers, allowance assignment and replacement, and delegated transfers. Each test deploys a fresh token to keep its state independent.

## 4i Events and failures

The tests use `truffle-assertions` to check insufficient funds, unauthorized spending, positive and zero Transfer events for both transfer methods, and Approval events. Additional checks cover allowance limits, rollback on failure, self transfers and zero address restrictions.

The recorded run passed all 16 tests. The execution transcript and deployment details are in `results/`. The environment used Truffle 5.11.5, Ganache 7.9.1, Solidity 0.5.1 and truffle-assertions 0.9.2.
