# 本次修订的使用与提交说明

## 改好了什么

本版以老师指定教程的 Casino 为基础，恢复了 `oraclizeAPI_0.4.sol`、Oraclize 随机数及 Ledger 证明检查，并使用补充文件演示的 Solidity 0.4.22。原始 Casino 文件和依赖来源也保留在代码包中，具体修复见 `CHANGES.md`。

正式配置为每轮 100 次下注，每个地址参与一次。第 100 次下注自动请求随机数。中奖者平分奖池并主动领奖，下一轮可以再次参与；无人中奖和整数余数转入下一轮。

网页使用当前的钱包连接接口，避免补充文件旧版 web3/webpack 配置失效。随机数流程没有改成 Chainlink。

## 本地运行

安装 Node.js 22.12 或更新版本及 pnpm 11，在项目目录运行：

```text
pnpm install --frozen-lockfile
pnpm test
pnpm run build
```

一个终端运行 `pnpm run chain`；另一个终端依次运行 `pnpm run deploy:local` 和 `pnpm run dev`。打开 `http://127.0.0.1:5173/?network=local`。钱包连接本地网络 31337，RPC 为 `http://127.0.0.1:8545`，使用节点提供的开发账号。

新一轮可执行 `pnpm run demo:local`，自动完成 100 地址下注、模拟回调和领奖。测试助手跳过真实 Ledger 证明，所以只能作为本地逻辑验证。网页会明确标注这一点。

## 还需要完成的外部步骤

2026年10月7日的只读检查发现：依赖中的 Sepolia 解析器能返回一个合约，但该合约回调地址为零地址，随机数会话密钥调用报 `InvalidFEOpcode`。原随机数路径目前没有通过检查；检查记录在 `SEPOLIA_READ_CHECK.json`。这一障碍需要确认原服务的可用配置，或由老师认可替代方案。本版没有擅自换回其他随机数服务。

公开部署必须选择 `contracts/Casino.sol` 的 **Casino**，不能部署测试目录中的 `CasinoLocalHarness` 来冒充正式版本。按 `SEPOLIA_DEPLOYMENT.md` 检查 Sepolia 上的原服务、部署合约、单独补充 oracle 费用，记录真实交易及回调。

再构建网页，将 `dist` 内的网站发布并固定到 IPFS，取得实际链接。源码、依赖目录及压缩包不是要发布的网站。
